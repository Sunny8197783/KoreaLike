# 18. 가시성(층 나누기) 설계 — 2026-11-25

> 상태: 구현·통합 완료(11-25 저녁). 결과는 §8. 마감 2026-11-26(목).
> 근거: `game/captures/vis/before*`(같은 시드 전 캡처 7시점×9장), `vis_stats.jsonl`, `run.log` 의 `[juice]` 줄, 진단 5건(contrast · vfx_layering · ui_text · crowd · genre_player).
> 원칙: **덜어내서 보이게가 아니라, 층을 나눠서 보이게.** 타격감(히트스톱·흔들림·섬광·효과음)과 먹·한지·주색·백 색감은 줄이지 않는다.

## 0. 한 줄 결론

친구가 본 '난잡함'은 이펙트 양 때문이 아니다. **이미 설계한 층(art_render_layers L09·L10·L12·L13)과 혼잡 대응 장치가 실제 화면에 연결되지 않아서**다.

- 적 MultiMesh 셰이더(`enemies/enemy_crowd.gdshader`)에 `crowd_dim`·`flash_keep`·`pullil_pulse` 유니폼과 흰 무구 비트 512 처리가 없다. 값은 쓰이지 않는 `shaders/enemy_instanced.gdshader` 에만 있다. 그래서 무리 감광·번쩍임 솎기·흰 무구 외곽선 번쩍임·기색 박 맥동이 GPU에서 모두 꺼져 있다. `[juice] flash_keep_min=0.25` 는 CPU 값일 뿐이다.
- 문턱도 '수백 마리' 가정이다. 감광 n0=150, 숫자 군중 모드 crowd_n≥120. 정상 런의 화면 일반 잡귀는 20~46 이다.
- 그리기 순서가 설계와 반대다. 플레이어 z2 < 앞줄 적 z3 < 적 탄 z4 < 내 VFX z5 < 재 z6 < 숫자 z20.
- 화면 가운데 글을 그리는 주체가 다섯인데, 하나만 고르는 중재자가 없다.

적 수 줄이기는 하지 않는다(근거 부족, 시뮬레이션이 갈라져 전/후 비교가 깨진다).

## 1. 층 설계 (명도·채도·그리기 순서)

### 1.1 값(명도) 층 — 위에서 아래로

| 층 | 대상 | 색 / 명도 목표(상대휘도 L) | 비고 |
|---|---|---|---|
| W 순백 | 해원 빛기둥(처치 순간), 정예·첫 해원 | #ffffff 가산 허용, L≈0.9 | '백'은 해원 한 뜻만 |
| 위험 | 적 탄, 원귀 테, 보스 예고 테두리 | 탄 심 #a9caf5 + 먹 1px 테 + 청 #5f93de 링 / 원귀 #c8322d + 먹 | 항상 불투명, 최상단 |
| 플레이어 | 무당 + 금 테 | 몸 원본 + 테 안 1px 금 #f5d66b, 바깥 1px 먹 #0e0b16 | 금 = 무당만의 표지 |
| P 한지 | 흰 무구 스파크·흰 무구 피격 외곽선 | ≤0.72 (흰 스파크 modulate 0.82,0.80,0.76) | 몸 전체가 아니라 외곽선만 |
| 주 | 붉은 무구 피격 2틱째 잔광, 붉은 숫자 | jk-hi #e4604f | '베였다' |
| 무리 | 일반·미니언 잡귀 | 상시 ×0.88 + 밀도 감광 | 외곽선 #1a1a1a 유지 |
| 영가 | 아군 행렬 | 따뜻한 넋불빛(#d9c9a3·#8c7a5e, 황토 기미 0.25) + 반투명 α0.72 (11-25 마감 수정: 청회색이 창백한 귀신과 섞임) | 차가운·불투명 귀신 무리와 색상·투명도로 갈림 |
| 바닥 | 배경·장판 채움 | L 0.006~0.06 | 손대지 않음 |

**플레이어 테 색 판정:** 진단이 금(#f5d66b)과 주색(#e4604f·#c8322d)으로 갈렸다. 금으로 정한다. 주색은 붉은 무구 피격 잔광, 원귀 테, 합일 붉은 바닥과 겹친다. 금은 합일 바닥 위에서도 분리된다.

### 1.2 무리 감광 수치 (판정)

- 진단 제안: 35/165, 24/120, 16/64, 24/96. **n0=24, span=96(화면 일반 잡귀 120에서 최대)** 로 정한다.
  - 정상 18:00(26~33마리) d≈0.03~0.09, crowd 19:30(46~58) d≈0.23~0.35, weak(190) d=1.
- 셰이더 세기: 명도 ×(1−0.30·d), 채도 ×(1−0.45·d). 그 앞에 상시 `crowd_base=0.88`.
  - d=1 일 때 최종 sRGB 약 ×0.62. 달걀귀신 중앙값이 바닥보다 여전히 6배 이상 밝다.
- 제외: 풀릴 기색(bit1)·원귀(bit4)·외곽선 픽셀·정예·보스·적 탄. 피격 플래시와 기색 테는 감광 **뒤에** 칠한다. 그래서 맞는 순간 대비는 오히려 커진다.
- 설정 '무리 어둡게': 끔(base 1.0, d 0) / 보통(×1.0) / 강하게(d×1.4, 상한 1).

### 1.4 가림 규칙

- 앞줄 잡귀를 뒤로 보내는 창: `kyf - ply < sp_body_h[s] + 2` 이고 `|dx| < 22`. 적 수 조건(`_crowd_unhide_n` 90)은 없앤다(0).
- 무적 점멸: 숨김 틱에 스프라이트를 지우지 않는다. 먹 실루엣 + 금 테로 바꾼다. '맞았다' 명멸 주기는 그대로다.

### 1.5 해원 빛기둥 (판정)

- 각 0.25초 창의 첫 2장과 정예 이상은 지금처럼(가산·풀 길이).
- 화면 일반 잡귀 ≥40 이면: 창 상한 6→3, 3번째부터 일반 블렌드 α0.75, 수명 ×1/1.5, 광원 펄스 1.0→0.5.
- 무당 40px 안 해원은 시트를 빼고 재·광원(0.6)만 낸다.
- 흰 무구 스파크는 modulate (0.82,0.80,0.76) 로 P 명세(≤0.72)에 맞춘다. 에셋은 그대로.

### 1.6 내 공격 색 언어

- 붉은 무구 피격: 틱0 한지(임팩트), 틱1 jk-hi 단색 잔광.
- 흰 무구 피격: 외곽선만 한지(bit 512).
- 숫자: 붉은 = #e4604f, 흰 = #f2ece0, 치명 = #e8b931. 모두 먹 2px 외곽선(치명 팝 3px).
- (후순위) 가산 지정 무구 시트(월도·작두 충격파·호작도·사인검)를 실제 가산으로 그리고, 고리 선 밑에 먹 1px 받침.

## 2. 글·띠 우선순위 규칙

### 2.1 화면 구역

- **위 띠**(y 60~122): 위험·할 일 전용. 예고 띠(정예·보스), 시련 안내판, 거리 카드. 한 번에 1개(이미 있는 상호 회피 + 가운데 슬롯).
- **가운데 슬롯**: 화면 가운데를 덮는 큰 글. **동시에 1개.**
- **가장자리**: 맛보기 글. 공수 인용·길흉 상자 결과(왼쪽 위, 무구 칸 아래), 붓 추임새(x 0.14 / 0.86, y 0.62), 힌트 줄(왼쪽 아래 x 8, y h−58, 폭 ≤260, 2줄).
- **플레이어 안전 상자**: 플레이어 화면 좌표 x±72, y−72~+16 안에는 화면 공간 글을 그리지 않는다.

### 2.2 가운데 슬롯 (Juice)

```
Juice.claim_center(owner: StringName, prio: int, sec: float) -> bool
Juice.center_busy(min_prio: int = 0) -> bool
Juice.release_center(owner: StringName) -> void
```

- 지금 주인보다 우선순위가 낮으면 false. 같거나 높으면 차지한다. 시간은 실시간(히트스톱에 안 늘어남).

| prio | 주인 | 차지 못하면 |
|---|---|---|
| 4 | trial_hud 큰 글자(해결·합일 호명 '산이—' '다 실렸다!') | — |
| 3 | 보스·정예 경고(가운데에 뜨는 경우), 레벨업 | 0.5초 뒤 재시도 |
| 2 | 거리 카드, hud 거리 슬램 | 0.5초 뒤 재시도(최대 2초), 이후 버림 |
| 1 | 붓 슬램 force('길닦음 ×N') | 버림 |
| 0 | 붓 추임새 | 버림(연속 굿 칩 팝만) |

### 2.3 개별 규칙

- 합일(HAPIL_OMEN 이후)에는 거리 카드를 띄우지 않는다. 시계 아래 거리 줄이 대신 말한다.
- `gs_hapil_word` 는 위 레인에 다시 띄우지 않는다(같은 말 중복).
- 공수: prio<2 는 8초 간격. 예고 띠·시련 안내판이 떠 있으면 버린다. 레인 수명 2.5→2.0초, 대기열 2→1.
- 길흉 상자 결과: 패시브는 `name_ko`, 같은 이름은 '초혼 적삼 ×3' 으로 합친다(원시 ID 버그).
- 거리 카드: 먹 띠(α0.55, 위아래 단청 1px) 위에, 띠 아래 끝 ≤ y122. 표시 2.4초.
- trial_hud 큰 글자 띠 아래 끝 ≤ y122(by2 0.36→약 0.26).
- 힌트 줄 보류: 가운데 슬롯 사용 중, `Juice.number_crowd`, 화면 잡귀 ≥60, 합일 중이면 prio<3 은 미룬다(나이 멈춤). prio 3 은 1.5초만.
- 붓 추임새: 콤보 20 단계는 붓 대신 연속 굿 칩 팝. 40 이상만 붓. BANNER_SCALE 1.5→1.25.
- 영가 수 라벨('40/24'): 정원을 매번 다시 읽고, 처음 가득 찬 순간·5 단위 변화에만 1.5초. 위치는 몸 밖(foot+(16,10)).

## 3. 피해 숫자 규칙

- 군중 모드 켜기: 기존 조건(합일·보스·작두거리) **또는** 화면 일반 잡귀 ≥40 **또는** 살아 있는 숫자 ≥24 가 0.5초 이어짐.
- 끄기: 잡귀 <30 이고 숫자 <14 가 1초 이어짐(이력).
- 군중 모드: 일반 숫자 끔. 치명·정예·보스·플레이어 숫자와 합산(merge/cluster)은 남김. 상한 16.
- 평시 상한: `combat_core feel.dmg_num.max_visible` 48→32, `local_cap` 3→2, `near_cap` 5→3.
- 작은 숫자 거르기: 최근 2초 최대 타격이 20 이상일 때, 일반 숫자가 그 8% 미만이면 새 칸을 만들지 않는다(같은 키 합산은 함).
- 화면 밖 128px 넘는 일반 숫자는 만들지 않는다.
- 무당 몸 상자(±14, −40~+4) 안에 생기면 상자 위로 옮긴다(플레이어 숫자 제외).
- 잡귀 ≥40 이면 일반 숫자 α0.8. 치명·정예는 1.0.

## 5. 수용 기준 확인 방법

### 5.0 공통

- 같은 명령으로 '후'를 찍는다(프로젝트 루트):
  - `bash tools/vis_capture.sh after`
  - `PICK=random bash tools/vis_capture.sh after_crowd`
  - `AT=1080,1170 EXTRA="--start-sec=1060" bash tools/vis_capture.sh after_weak`
  - `PYTHONIOENCODING=utf-8 python tools/vis_measure.py game/captures/vis/before game/captures/vis/after` (crowd·weak 도 같은 짝)
- **시뮬레이션 동일성 먼저:** 각 시점의 플레이어 좌표·화면 적 수가 before 와 같아야 한다. 다르면 화면 코드가 게임 난수를 썼다는 뜻이다. 그 수정부터 찾는다.
- `bash tools/godot_check.sh` 오류 0(`LOG_TAG=vis_after`).

#### 5.2 vis_probe 글 분류 정의 (D_text_ui, 11-25 갱신)

- 읽는 값: 글 주인(hud·haewon_system·guide·wave_presenter·trial_hud)이 **이번 프레임에 실제로 그린** 사각형 `vis_rects`(640×360 기준, 그린 프레임 번호와 함께). 예전처럼 '타이머가 남았는가'로 세지 않는다. 그래서 대기 중인 거리 카드(아직 안 그림)는 세지 않는다.
- 고정 분류: `top:lane`(위 공수 레인 y64) · `top:wave_band`(예고 띠) · `top:trial`(시련 안내판) · `edge:lane`(왼쪽 위 가장자리 레인: 맛보기 공수·길흉 상자) · `center:wave_card` · `center:trial_big` · `center:geori_slam` · `center:levelup`.
- 위치 분류(`pos:` 키 = 붓 슬램·힌트 줄): 사각형 중심이 가운데 상자(x 0.25~0.75W, y 0.2~0.75H) 안이면 `center`. 밖이면 x 가 좌우 25% 안 → `edge`, 위 → `top`, 아래 → `bottom`.
- 화신 원 카드 두 장(시련 예고~확인)은 월드에 붙은 이름표다. 예전 값과 비교하려고 `center:trial_cards` 로 **1개** 센다. 안전 상자 계산에서는 뺀다.
- `center_n` = 위 center 개수. `safe_n` = 플레이어 안전 상자(플레이어 화면 좌표 x±72, y−72~+16)와 겹치는 화면 공간 글 수(world 제외). 겹치면 texts 에 `SAFE!<이름>` 을 붙인다.
- 장마다 더 남기는 값: `fps`(Engine.get_frames_per_second), `draw_calls`(RENDERING_INFO_TOTAL_DRAW_CALLS_IN_FRAME), `center_owner`(Juice 가운데 슬롯 주인, 비었으면 "").

### 8.4 남은 것

- ② 수치 목표(순백 −50%, 한지 −40%)는 weak 에서 못 맞췄다. 남은 흰 덩어리는 주로 고리로 수십 마리를 한꺼번에 풀 때의 해원 디졸브와 빛기둥이다. 이것은 '해원'(백) 층이 맞다. 더 줄이면 해원 보상감이 준다. 사람 플레이로 판단할 것.
- 고리 닫힘 섬광이 칸(격자) 모양 사각형으로 잠깐 보인다(after 03:00 shot_01, 15:00). 원래 있던 연출이다. 정교함 면에서 원형 마스크로 바꿀지 검토할 것.
- 성능: 00:04 릴리스보다 15~23% 느리다(60fps 는 넘음). draw call 은 같으므로 스크립트 쪽이다. 마감 뒤 프로파일러로 볼 것.
- 원귀는 캡처에 나오지 않아 그림으로 확인하지 못했다(코드·셰이더만 확인).
- `vis_capture` 의 fps 는 PNG 저장·화면 읽기 정지가 섞인다. 성능은 `fps_clean` 이나 캡처 없는 `[autotest]` 줄로 본다.

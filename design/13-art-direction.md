- **피벗 규칙:** 가장 아래 불투명 픽셀 행(발끝, 치맛단)이 피벗 y와 ±1px 이내여야 한다. 떠다니는 귀신은 '가상 발끝' = 그림자 중심. 린트로 검사한다(12장).
- **여백 규칙:** 외곽선 셰이더(풀릴 기색 1px)와 아틀라스 번짐을 막으려면 사방 2px 투명 여백이 반드시 있어야 한다. 아틀라스 패킹 시 2px extrude를 쓴다.
- **설계 의도:** 피벗이 하나라도 어긋나면 y정렬 가림이 깨지고 행렬 영가가 '떠' 보인다. 캔버스 크기는 캐논 3.1 등급 범위 안에서 8px 단위로 고정해 아틀라스 패킹을 단순화한다.

| 대상 | 기본 형태 | 규칙 | 설계 의도 |
|---|---|---|---|
| 무당(플레이어) | **수직 삼각형**: 갓·고깔 꼭짓점 → 넓게 퍼지는 소매·치맛자락 | 실루엣 상단에 뾰족한 점 1개 이상, 하단 폭 ≥ 상단 폭 × 2 | 군중 속에서 '삼각형 하나'가 곧 나다 |

**모티프 사전 (모든 에셋이 이 6개 안에서 장식을 고른다):** ① 실·매듭(한=맺힘, 해원=풀림) ② 한지(종이 넋·지전·부적) ③ 무명천(길베·고풀이) ④ 불(촛불·등불·혼불) ⑤ 오방색 ⑥ 먹선(붓 터치, 민화 호랑이).
- **설계 의도:** 모티프를 6개로 묶으면 서로 다른 작업자가 만든 에셋도 한 세계로 보인다. 서양 퇴마물의 십자가·마법진·룬 문양이 끼어들 틈을 원천 차단한다.

## 2.5 셰이딩·광원 방향 (베이크)

### 2.6.2 '원혼 구슬 소(청)' 해석 [캐논 준수 해석]
캐논 4.8.1은 원혼 구슬을 "소(청)·중(황)·대(적)"로 정했다. 그런데 오방 청 `#2a5caa`는 적 탄 전용(캐논 6.1)이다. 이 충돌을 다음처럼 푼다.
- 구슬 소는 **청록 변이 `cr` 램프**(`#2f8c86` 본체, `#9fe0d4` 하이라이트)로 칠한다. 한국어 '청(靑)'은 푸른색과 초록 모두를 포함하므로 캐논 명칭 '청'과 어긋나지 않는다.
- 형태로 한 번 더 구분한다: 구슬 = **마름모 6×6px + 바닥 그림자 + 박마다 2px 위아래 bob, 정지**. 적 탄 = **원 + 흑 코어, 이동, 그림자 없음**.
- 설계 의도: 색 하나만으로 구분하지 않는다(색각 이상 대응). → 15장 열린 질문 Q3에서 CD 확인 요청.

  4. **재질 패턴으로 정체를 말한다:** 면을 채우지 않고 선·결로 그린다. 방울·천음 = **음파 링 선**(1px 동심원 3줄, 내부 채움 0%), 장구 = **링 선 2줄 + 바깥으로 흩어지는 2px 점열**(내부 채움 0%), 쑥물·삼물 = **물결 선**(cr 보조), 부채 = **바람결 곡선 3줄**, 넋전·지전·넋꽃비 = **종이결**(접힌 자국 1px 대각선·엽전 구멍), 길베 무구·베가르기 = **무명 결**(가로 2px 간격 줄무늬), 오방기·오방진 = 도상 변이 5색(백 기 = `hj`), 소금 = **결정 점열**. 오라·장판 내부를 비워 두면 그 안의 기색 테가 가려지지 않는다.
  - 순간 해원 연출(`vfx_haewon_rise`, 길닦음 매듭·채움, 천도, 고 매듭 풀림 등, 색 역할 `W`)만 순백을 쓴다. **상시 순백**은 기색 테·영가·길베 3종뿐이다.

```
N  = 화면 안 일반 잡귀(enm_*) 중 풀릴 기색이 아닌 개체 수, 4Hz 갱신
d  = clamp((N − 150) / 450, 0, 1)
명도 배율 = 1 − 0.22 × d ;  채도 배율 = 1 − 0.35 × d   (0.5초 선형 보간)
제외: 풀릴 기색 개체, elite_*/mboss_*/boss_*/chaser_*/avatar_*, 적 탄
```
- 구현: 적 공용 머티리얼의 유니폼 2개. 개체별 계산이 없어 비용이 0에 가깝다.
- **설계 의도:** 풀릴 기색 개체는 감광에서 빠지므로 무리가 커질수록 '흰 테 + 원래 밝기'가 상대적으로 떠오른다. 해원 동선(P1)을 군중 속에서 찾게 하는 장치다.

### 2.10.7 플레이어 VFX 알파 예산
```
C = (플레이어 VFX가 덮은 1/8 해상도 셀 수) / 3600        # 80×45 커버리지 버퍼
alpha = clamp(사용자알파 × (1 − 0.5 × clamp((C − 0.25)/0.25, 0, 1)), 0.35, 사용자알파)
대체 휴리스틱(저사양): 활성 플레이어 VFX 인스턴스 > 120 이면 alpha × 0.75
```
- **설계 의도:** 빌드가 폭발할수록(후반) 화면을 덮는 내 이펙트가 자동으로 투명해진다. 캐논 6.1의 "기본 70%, 옵션 30~100%"를 존중하면서 상한만 동적으로 깎는다.

# 4. 캐릭터별 애니메이션 리스트

> 원천 데이터: `data/art_anim_specs.json`. 아래 표의 `방향`은 **저작 방향 수**다(4 = 남·동·북·서, 3 = 남·동·북 + 서는 동 미러, 2 = 남·동 + 서 미러·북은 남 재사용, 1 = 정면). 프레임 합계 = 프레임 × 방향.

## 4.1 공통 규칙

### 4.1.1 방향 선택 (런타임 4방향)
```
θ = atan2(-vy, vx)   # 화면 기준 이동 각도, 0° = 동
동 : -55° ≤ θ ≤ 55°        서 : |θ| ≥ 125°
북 : 55° < θ < 125°        남 : -125° < θ < -55°
히스테리시스: 현재 방향 구간 경계를 10° 더 넘어가야 전환
정지 시: 마지막 방향 유지
```
- **설계 의도:** 동·서 구간을 넓게(110°) 잡아 대각선 이동도 측면 3/4로 보인다. 측면이 지물(부채·월도)과 소매 문양을 가장 잘 보여 주고, 빙의 오버레이 비용도 4방향으로 고정된다(캐논 6.2).

### 4.1.2 재생 우선순위 (플레이어)
`death` > `bingui`(정지 중일 때만) > `hurt`(2프레임 덧씌움) > `walk` > `idle`.
- `bingui`: 트리거 순간 이동 속도가 0.2u/s 미만이면 몸 애니메이션을 재생한다. 이동 중이면 **몸은 계속 걷고** VFX(빛기둥·문양 스윕·오라 점화)만 재생한다. 캐논 3.2.10 '화면 비정지'를 지키고 이동 입력을 뺏지 않는다(캐논 2.2 "폭주 이동 강탈" 폐기 취지).
- `hurt`: 현재 방향의 2프레임(밀림 1px + 복귀)을 위에 덮는다. 걷기 프레임 카운터는 계속 진행.

### 4.1.3 적 시각 상태기계
```
SPAWN(4~6f) → MOVE ⇄ ATTACK
MOVE/ATTACK --(r ≤ 0.35)--> PULLIL [얼굴 소켓 전환 2f, 외곽선 ON, 이동 애니메이션 재생 ×0.7]
PULLIL --(백 피해로 한 0)--> HAEWON [몸 디졸브 0.3s + vfx_haewon_rise → 영가 생성]
PULLIL --(결단타)--> TOECHI [vfx_gyeoldanta_cut + vfx_toechi_burst + 살 알갱이]
PULLIL --(12s 경과)--> MAETIM [vfx_maetim_knot, 얼굴 역전환 2f] → MOVE
MOVE/ATTACK --(한 파열)--> TOECHI [vfx_toechi_burst + 살 알갱이]
정예 이상: 매듭 잠금 없음 → 적 무구 마지막 타격 시 TOECHI (캐논 3.2.2 c)
```
- 퇴치·해원에는 **종별 사망 애니메이션을 만들지 않는다.** 공용 VFX + 셰이더 디졸브로 처리한다(정예 이상은 전용 finale 있음).
- **설계 의도:** 일반 잡귀 12종 × 사망 2종 = 24 시트를 아끼고, '퇴치=방사·해원=상승'이라는 공용 문법을 모든 종에 똑같이 적용해 학습 비용을 0으로 만든다.

## 5.3 모자 처리
- 모자가 있는 무당(만신 흑립, 박수 전립, 심방 갓)은 스프라이트를 **몸 레이어 + 모자 레이어**로 분리한다. 빙의 ≥1이면 모자 레이어를 끄고 `nohat_head_layer`(4.2) + 머리 오버레이를 그린다.
- 모자 없는 무당(단골·명두)은 머리 오버레이를 바로 얹는다.
- 머리 오버레이는 32×32 안에서 원래 모자 실루엣(만신 갓 폭 26px)을 **완전히 덮도록** 설계한다(덮지 못하면 무모 머리 레이어가 대신 보이므로 오류가 아님).
- **설계 의도:** 모자를 '분리'하는 수작업 144프레임이 '모든 무당 × 모든 신령' 시트(60세트)를 그리는 것보다 훨씬 싸다.

# 8. UI 아트

> 레이아웃·상호작용·접근성 규칙은 `11-ux-ui-hud.md`가 소유한다. 이 장은 **UI에 필요한 아트 에셋과 그 규격**을 정의한다.

## 8.1 UI 캔버스·폰트

| 항목 | 값 | 설계 의도 |
|---|---|---|
| UI 논리 해상도 | **월드와 같은 640×360**(덱 640×400). UI 아트 1px = 월드 1px | 픽셀 크기 통일(mixel 없음) |
| 본문 폰트 | **Galmuri11**(줄 높이 12px), 보조 **Galmuri9**(10px). SIL OFL 1.1 | 한글 픽셀 폰트 중 라이선스가 명확하다. 원작자 표기상 Galmuri11 = 12px, Galmuri9 = 10px로 정수배 렌더 |
| 스팀덱 가독성 | 최소 글자 = Galmuri9 10px × 2배 = 20px(덱 1280×800) | Valve 기준 "가장 작은 글자 9px 이상(1280×800), 권장 12px" 충족 |
| 일·중 | **Galmuri + Fusion Pixel(둘 다 SIL OFL) 혼용**(캐논 v1.2 D-56). Galmuri가 덮지 못하는 가나·간체 한자는 Fusion Pixel로 채운다. 넋두리 300줄 커버리지 검사(W21) | 캐논 5.1: 한·영·일·중 간체 |

| 붓글씨 타이틀 | 손 레터링 스프라이트: 거리명 8종(6거리 + 보스 대면 + 명부), 스테이지명 5, 얼씨구 4, 로고 1 | AI 가짜 한글 금지(9장). 붓글씨는 폰트로 대체 불가 |

# 11. PixelLab 제작 파이프라인 계획

## 11.1 원칙
1. **보이는 목표를 먼저 승인한다.** 0단계 '비주얼 타깃'(640×360 한 장면)을 승인하기 전에는 대량 생성을 하지 않는다.
2. **가족 단위로 만든다.** 같은 등급은 같은 승인 시드(style reference)로 작은 묶음씩 만든다.
3. **생성은 초안, 승인은 사람.** 팔레트 고정 → 정규화 → 네이티브 스케일 검토 → 인게임 검토를 통과해야 승인한다.
4. **출처를 기록한다.** 모든 파일은 `art/manifest.tsv`에 생성 ID·도구·모드·날짜·비용·편집자를 남긴다(Steam 생성형 AI 공개 항목: '개발 중 사전 생성 콘텐츠'로 답할 근거. 런타임 생성은 없음).

## 11.3 프롬프트 카드 (불변 블록 + 가변 블록)

```text
[INVARIANT — 모든 행위자 공통, 영어로 전달]
VIEW: low top-down 3/4 view (~20 degrees), facing <DIR>
STYLE: crisp pixel art, single color black outline (#1a1a1a), 3-tone cel shading,
       light from upper-left, shadows hue-shifted toward deep violet, no anti-aliasing,
       no dithering on small sprites, transparent background
WORLD: night shamanic ritual (gut) in Joseon-era Korea, Korean folk aesthetics
EXCLUDE: text, letters, Japanese armor, Chinese wuxia robes, oni horns, crosses,
         pentagrams, blood, gore, skulls, background scenery, frames, duplicates

[TIER BLOCK — 일반 잡귀]
PALETTE: desaturated ash grey-blue robes (#26292e..#aab1b5), never pure white,
         drooping silhouette, head bowed, feet hidden or blurred
SIZE: <32|40|48>px canvas

[TIER BLOCK — 영가]
PALETTE: clean warm white (#f2ece0, shade #d6cfc1), calm relieved face, upright candle-like silhouette

[ASSET BLOCK]
SUBJECT: <예: Korean egg ghost — featureless oval egg-shaped face, mourning robe,
          carrying one child's rubber shoe>
```
- 불변 블록은 문서 버전과 함께 고정한다. 바꾸면 이미 승인된 에셋과 표류(drift)가 생긴다.
- PixelLab `create_character` pro 모드와 `animate_character` v3·pixminimax는 `palette`/`max_colors` 인수를 받는다 → 마스터 팔레트의 등급별 부분 집합을 넘긴다(잡귀 = `mk`+`hk`+`gh`/`gr`+`sk` 일부, 최대 12색). v3 캐릭터 생성은 팔레트 인수를 받지 않으므로 생성 후 `reduce_colors`로 고정한다.

## 11.4 단계별 생산 흐름 (에셋 1개)

```
[P0 브리프] 이 문서의 표 1행 + 프롬프트 카드
   ↓
[P1 생성] PixelLab (승인 시드를 style/reference로)            → manifest status=generated
   ↓  G0: 정체성·시점·비율·고증 금지 목록 1차 확인(불합격 → 삭제·재생성, 최대 3회 후 수동 제작)
[P2 정규화] 팔레트 고정 → 반투명 픽셀 제거 → 트림 + 2px 여백 → 피벗 정렬 → 프레임 수 선별
   ↓  G1: art_lint 자동 검사(12.2)                              → status=cleaned
[P3 손질] 픽셀 아티스트: 클러스터 정리, 외곽선 연속성, 프레임 간 볼륨 흔들림 제거, 앵커 찍기
   ↓  G2: 네이티브 스케일 ×1·×3, 배경 3종(선바위 굿당 흙·남도 갯마을 갯벌·길베 흰 천) 위 검토
[P4 통합] 아틀라스 패킹, 엔진 임포트(Nearest), 애니메이션 타이밍 입력
   ↓  G3: 인게임 검토 + test_readability_1000                  → status=in_engine
[P5 감수] 고증 체크리스트(3.8) — 묶음 단위 월 1회 자문
   ↓  G4
[P6 승인] 아트 디렉터 서명                                      → status=approved
```
